## 二 本輪範圍與預設選擇

基本方向為保留 NMT、中英一般術語表及既有硬性資料保護。保留每訊息單次請求、沒有品質重試、沒有失敗後自動切換引擎，並維持 👆／🚧、群組指令、私訊、語音及採集開關既有契約。

9/29 已確認的英數符號原樣保留規則維持，包括 `follow-up`、`alloys/blends` 等字串。因此本輪不能把這三筆中文可讀性代價算成已修正缺陷，也不能透過重寫原文或隱藏例外繞過規則。

現行真人資料僅作本機審閱及離線回歸。對外翻譯評估使用合成案例，不把歷史對話、身分映射或私密附件送到新模型。沒有原生提及 metadata 的歷史資料，僅能支持本文審閱；需要完整重播時另建合成提及事件，不能宣稱重建了歷史原請求。

維持保存至手動清除、原始 userId 儲存及不保存被拒候選譯文的既有政策。本輪不新增 OCR、向量資料庫、整群長期記憶、通用跨群快取、自動資料刪除或常駐實例。

## 四 觀測與去重設計

### 每筆翻譯的資料契約

新增資料採相容欄位／schemaVersion，不回填猜測值；歷史缺少的費用、原因及耗時標示 unknown。translation operation 使用穩定事件關聯加上唯一操作識別，不能只靠 Cloud trace，因一個 webhook 可以包含多個事件。

| 資訊 | 設計要求 |
|---|---|
| 操作狀態 | skipped、prepared、provider_started、provider_succeeded、quality_rejected、service_error、provider_unknown 分開；LINE 發送結果另列 |
| 用量 | 原文碼點、實送 contents 碼點、輸出碼點；區分預留量與已知送出量，不能把 reservation 當帳單 |
| 成本來源 | 引擎、來源／目標語言、術語表／保護版本、runtime 或 evaluation、計價版本 |
| 字元構成 | 正文、HTML／標記、輔助 contents；分類可加總回實際送出字元，不把 glossary 全表重複傳入 |
| 品質細節 | 原始安全拒絕細碼、失敗階段、保護類型計數；不記本文、候選譯文、姓名或 token |
| 時間 | 設定／採集、身分檢查、帳本、provider、驗證、LINE 各階段及總耗時；不能把 provider 時間冒稱手機延遲 |
| 零呼叫 | 純代碼、相同結果的本機返回、指令與略過須有 apiCalled=false 或明確 unknown；不能一律將 translated 算一次 API |

原 `nmtEvaluationBudget/approved-20260924` 持續累計、不歸零。每日／每月報表從事件／操作記錄產生，不直接往現行固定 categories 塞新鍵破壞驗證；需要帳本遷移時另有版本及保守兼容設計。記錄失敗遵循現行行為，不能為了觀測而放寬計數失效即停止的控制。

### 去重與不確定狀態

先完成設計與故障案例，再寫實作。去重範圍是同一來源事件；不同事件即使文字相同，仍是不同使用者操作，不當作重送。

- 優先使用 webhookEventId，缺少才沿用可信的群組加 messageId。兩者皆無時標示無法可靠去重，採既有入口契約，不宣稱具備完整去重。
- 以資料庫交易取得處理權，並記錄 owner attempt／fence／版本。並行第二個請求不執行翻譯；完成事件不重新翻譯或送 LINE。
- 帳本預留及操作狀態必須可原子關聯，避免先寫 ledger、再寫操作狀態時當機造成重複預留。保留原 ledger 累計與政策歷史；設計兼容舊 runtime 及回復路徑。
- 呼叫前持久記錄 provider_started。開始前已能證明未呼叫的失敗才可在明確狀態下恢復；呼叫後逾時或程序終止列 provider_unknown，不因 lease 到期就重呼。這是避免重複費用的取捨，可能讓極少數不確定事件需要人工處理，不能承諾外部 API exactly-once。
- 翻譯結果已驗證後，與 LINE 發送狀態分開保存；送出後逾時／崩潰列 delivery_unknown，禁止用新 replyToken 盲目補送。沿用既有明確 HTTP 400 提及格式降級一次的規則。
- 事件狀態保留先沿用手動清除，不順便加 TTL；保留天數若影響長期費用，另列產品決策。

去重驗收要涵蓋並行重送、跨實例、帳本交易中斷、呼叫前／後崩潰、回覆已接受但未寫完成、多事件 webhook 及記錄關閉。不以單純多次呼叫 saveOriginal 的測試代替端到端成本與回覆驗證。

## 五 中英品質改善設計

### 領域術語

第一批以 10～20 個明確詞組為目標，不追求詞條數。候選包括海關稅則／稅號、貨櫃／櫃門、尾款／催收尾款、預付款／跟進付款、商務確認回覆；以實際問題與相鄰反例決定是否加入。

| 正例 | 必須同測的反例 |
|---|---|
| 海關稅號 → tariff code／HS code | 納稅人識別號 → tax ID；不得被改成 HS code |
| 裝櫃語境的櫃門 → container doors | 家具櫃門仍為 cabinet door |
| 催收剩餘款項 → collect the remaining balance | 帳戶餘額、一般 balance 不套尾款 |
| 今天跟進預付款 | 今天已支付預付款、明天才跟進，時間與完成狀態不可合併 |
| Fine 作回覆表示同意 | a fine、fine powder、I'm fine 等不能全域替換 |
| 打電話給 A | 叫某人 A、召集 A、命名等其他 call 義項 |

一般 glossary 是詞彙工具，不會自動推理語境。會在其他情境造成錯誤的單字不能直接全域加入；要使用足夠明確的詞組、可靠的領域選擇，或留待上下文階段。只靠術語表無法處理的問題應保留 finding，不以錯譯後替換文字掩蓋。

新增術語版本，不覆寫既有雲端 glossary。執行前核對目前 zh-en-v12／en-zh-v9 實際資源及雜湊，再命名候選；保留回復所需舊版本與同版規則。若保護規則把詞組凍結，必須先證明與 glossary 的交界行為，不能跳過測試。

### 硬性保護與語意關係分層

硬性契約繼續檢查代碼、原生提及 occurrence、金額、精度、幣別、數量、分母、段落及輸出長度。另針對已證明有風險的角色／動作／時間／否定關係建立可解釋的檢查與正反例。

提及同名不等於同一人；只保留 @ 次數不足以防止「受確認者」與「收訊者」混淆。時間詞存在也不足以保證修飾正確動作。檢查涵蓋不到的語意不得宣稱已驗證；也不能為達成低拒絕率放鬆必要保護。

Fine 等固定短句候選若採本機翻譯，須與目前 OK／Yes／No 的略過規則分開：它是產生譯文，不是新增靜默／👆 黑名單。其確切啟用範圍在 B 實作前列出，不影響含其他文字、提及或數字的訊息。

## 六 測試與驗收

只改檢查／還原且 wire 不變時優先重播；改了原文、標記、術語、模型或上下文就不能把舊 API raw 當新行為證據。真實對話缺失的 mention metadata、候選譯文及附件不補猜。

不得以「全部回覆成功」「拒絕率下降」或「總測試數增加」取代語意品質驗收。允許未知或待決項目存在，但它們必須保持未完成，不能算成 pass。

上下文研究的初始提案為同群被引用原文 1 則、最多 500 個 Unicode 碼點、30 分鐘內；這是待驗證的實驗參數，不是現行規則。超長、過期、找不到、跨群、先後矛盾或記錄已關閉時不自動擴大檢索，對齊資料使用政策後才決定產品行為。一般最近訊息補充暫不納入第一個實驗，避免把不同話題串錯。

上下文只作待翻譯資料，不是新指令；不翻歷史訊息、不拼出新承諾，也不從過去付款推定當前已付款。NMT 多份 contents 不等於上下文理解；候選必須有可驗證的上下文契約。沒有做到這點，就只交付實驗結論，不接 runtime。

候選路由若獲採納，在呼叫前選定且每則只走一個引擎，共用硬契約與失敗政策。風險判斷器本身須測誤分流，不能假設關鍵字永遠抓得到語意錯誤；無法辨識的情況保留限制。
