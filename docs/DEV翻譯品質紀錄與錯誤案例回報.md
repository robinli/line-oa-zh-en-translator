## 保存與完整性

`lineTranslationMessages` 保存群組、來源發言者、事件／訊息 ID、原始事件時間、入庫時間、訊息類型、原文或既有流程取得的語音逐字稿、成功譯文、回覆文字、處理結果及發送狀態。另記翻譯模式、方向、引擎、術語表、部署版本及可取得的 quotedMessageId，供跨版本比對與已保存上下文關聯；不保存 quoteToken。

- 包含翻譯停用、管理指令、正常略過、錯誤與限制阻擋。原文按首次收到內容保存。
- 原譯文與實際回覆分開；相同譯文改回覆 👆 時仍能查到原譯文。API 接受回覆不代表手機已讀或顯示驗收完成。
- 語音未取得逐字稿時只記可取得資訊與原因，不為採集新增辨識呼叫；圖片、貼圖、影片及檔案只記類型與訊息資訊。
- 不保存音訊或附件、品質拒絕候選譯文、replyToken、Secret 或 SDK 原始錯誤。人工回報的錯誤譯文屬管理者主動提供的案例內容，另外保存。
- 儲存以事件 ID／群組及訊息 ID 去重，保留首筆原文；完成狀態可補齊，重送不覆寫已完成結果。這不是整個 webhook 發送去重。
- 有限重試後寫入仍失敗，不阻擋翻譯回覆；安全診斷 `reason=quality_store_error` 不含本文或身分。資料庫本身不可用時無法靠該資料庫準確統計遺失訊息，因此分析須核對 Cloud Logging；無權讀取日誌時標示未知，不以零代替。
- `lineTranslationFailures` 保留既有用途與規格，與新的採集紀錄以事件 ID 關聯。

## 管理者私訊

指定 `LINE_OWNER_USER_ID` 可在一對一輸入 `/翻譯錯誤`，選擇搜尋紀錄或手動新增。一般私訊不保存為群組品質資料，`/我的ID` 維持原有行為。

搜尋可選四群之一或全部，預設最近七天，亦可指定日期；關鍵字比對原文或譯文。每次最多掃描 200 筆，結果五筆一頁；保留游標繼續搜尋，未掃完不宣稱完整無結果。

選取後顯示完整內容，填寫必填錯誤說明與選填建議譯文，再確認儲存。找不到來源時可手動填群組或未指定、方向、原文、錯誤譯文或未產生譯文、說明及建議譯文。

`lineTranslationErrorCases` 保存來源關聯、內容快照、回報者與時間，初始待分析，不自動修改術語表或翻譯程式。`lineTranslationReportSessions` 保存草稿及步驟，閒置 30 分鐘失效；支援 `/返回`、`/取消`。步驟按事件去重，交易確保重複確認只建立一筆案例；交易明確失敗時保留草稿；逾時可能有延後完成的交易，因此提示稍後確認結果，案例 ID 固定且重複確認不再建案。

只有指定管理者可查詢與新增；不能以顯示名稱取得權限。回報流程不呼叫翻譯 API。

## 本機匯出與分析

完成建置後，在已設定隔離 DEV ADC 的管理環境執行：

```powershell
npm.cmd --prefix functions run export:quality -- --project=line-auto-translate-bot-dev --from=2026-09-25 --to=2026-10-01
```

日期為 Asia/Taipei 且包含起迄兩日，請依實際啟用日調整。可加 `--group=群組名稱` 或原始 groupId；預設全部四群。輸出僅允許 `.local/` 下的子目錄，預設 `.local/quality-export/起日_迄日/`：

- `messages.jsonl`：依事件時間排序的交談與處理結果。
- `error-cases.jsonl`：期間內建立的人工案例。
- `summary.json`：群組／每日收到、翻譯、略過、失敗、回覆失敗與未完成紀錄，以及 Cloud Logging 接收事件去重數與寫入錯誤診斷。

匯出只將路徑與數量印至終端，不印交談內容。寫入錯誤診斷次數不等於精確遺失訊息數；不得僅以已入庫筆數宣稱完整。實際分析由使用者一週後另行提出。
