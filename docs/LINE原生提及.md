## 使用行為

群組文字翻譯可把已確認的稱呼轉為可點選的 LINE 原生提及。Wei bro、Wei brother 均使用使用者提供的同一個 LINE userId，英文大小寫與連續空格／Tab 不影響匹配；也支援手打 @Wei bro。

LINE 會以對方目前的 LINE 顯示名稱呈現原生提及，不會顯示原始 userId。單獨 Wei、Wei Brotherhood、網址及電子郵件不會被猜測為該人。程式只採用明確設定的稱呼或原始 webhook 的指定 userId，不由模型推定身分。

原訊息已有的原生 @ 提及會沿用其 userId；同名的兩個人仍分別對應。缺少 userId、@All、提及機器人、矛盾的對應或不合法 metadata 保留文字，不新增通知。

## 翻譯與發送流程

1. 照既有聊天室設定判斷是否翻譯；中文原生 @ 顯示名稱不影響正文方向。
2. 將原生提及文字與明確稱呼加入翻譯保護範圍；userId、群組 ID 與對應資料留在伺服器端，不加入模型輸入。
3. 翻譯引擎還原保護標記時，回傳各原文位置對應的譯文位置；不以顯示名稱搜尋猜測身分，因此能處理語序變更、Emoji 及重複名稱。
4. 原文與譯文相同時照原規則不回覆，也不為了新增 @ 而單獨發訊息。
5. 發送前用 LINE 群組成員 API 確認每個目標仍在目前群組；同人只查一次、查詢最多三秒，不儲存個人檔案。
6. 確認有效者透過 textV2 substitution 發送；查詢失敗或非成員只保留譯文中的稱呼。
7. LINE 明確回傳 HTTP 400 拒絕含提及回覆時，嘗試一次純文字回覆；網路逾時、429 或 5xx 不自動重送，避免在送達情況不明時重複通知。

每則來源最多處理 20 處指定提及。長譯文依 5,000 UTF-16 單位分段，不切開提及或 Emoji；正文的大括號會轉義以保留原樣。若轉義及分段超出 LINE 的五則回覆上限，完整譯文改用純文字發送。

本階段只處理群組的文字翻譯；一對一與語音回覆維持原有行為。中翻英群組的英文文字仍會略過。舊 google 引擎沒有可驗證的位置還原資料，使用該引擎時只回覆純文字。

## 設定

Firebase 參數 LINE_MENTION_ALIASES_JSON 是陣列，預設為 []。每筆包含 alias 與 userId；同一稱呼指定到不同 userId 時，整組別名設定不啟用並記錄不含資料的警告，原生提及仍可正常處理。

目前兩種稱呼的真實對應已寫入 Git 忽略的 .local/line-member-aliases.json 與 functions/.env.line-auto-translate-bot，狀態為 deployed，兩種稱呼的正式參數已核對一致。原有本機設定及上一版正式設定皆有備份；群組翻譯模式與開關未變更。不要將真實對應寫入程式、公開文件或測試資料。

已使用 business 引擎部署 lineWebhook 並生效；未新增雲端 IAM 權限。設定為 [] 可停止稱呼自動轉換，原文的有效原生提及仍會保留。若需回復全部舊行為，使用前一版已部署的程式。

## 正式部署驗證

- 正式 LINE_MENTION_ALIASES_JSON 中的 Wei bro、Wei brother 均與使用者指定的同一 userId 一致；引擎為 business。
- 有效簽章空事件 HTTP 200；無效簽章 HTTP 401，正確拒絕。
- 英文正文搭配中文原生 @ 名稱，在中翻英群組仍正確略過。
- 虛構代碼成功呼叫模型後略過相同譯文；另以包含原生提及的虛構事件驗證位置還原與相同譯文抑制，均 ignored=1、failed=0。
- 只讀查詢確認指定使用者是兩個驗證群組的成員；未向任何群組發送測試訊息或提及通知，實際顯示與通知效果尚待 LINE 使用端驗收。
- 新版本檢查時未見 ERROR 或別名設定失效警告；部署前的 266 項自動化測試、型別檢查及建置再次通過。
