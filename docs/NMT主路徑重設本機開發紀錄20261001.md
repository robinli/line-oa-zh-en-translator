建立日期：2026-10-01。狀態：**異形引號／可信範圍限縮版 M1／NMT-07 本機交付通過；原自動推斷候選 FAILED 保留，未做真實 NMT 對照、未部署**。

使用者在 [開發計畫](NMT翻譯主路徑重設開發計畫.md) 建立後明確要求「執行開發」。本次範圍是 NMT-00～07 的本機開發與檢查，主 Agent 負責唯一程式寫入，標準 verifier 獨立驗證。現行 DEV、已配置別名、付費暫停與既有品質 findings 維持原狀。

## 實作結果與能力範圍

中英新增 `nmt-direct` 候選。一般來源正文直接送 NMT；原樣片段另建 manifest，必要時才使用不可翻譯 HTML span。保護只處理明確字面內容，不解析一般數量、時間、角色或商務承諾來決定是否發送。

| 模組 | 責任 |
|---|---|
| [原樣指示](../functions/src/nmt-exact-directives.ts) | 各指示獨立的範圍證據與 resolved／ambiguous，不用其他 literal 作完整性證明 |
| [原樣政策](../functions/src/nmt-literal-policy.ts) | UTF-16 來源範圍、逐次 ID、段落、保留原因與 native 提及的內部偏移 |
| [傳輸 codec](../functions/src/nmt-transport-codec.ts) | 原文 plain／最少 HTML、一次傳輸解碼、段落與提及位置還原 |
| [字面完整性](../functions/src/nmt-integrity.ts) | 宣告片段內容、原段落及全訊息出現次數；不掃普通輸出數字 |
| [原文 adapter](../functions/src/nmt-direct-translator.ts) | 一次 NMT 請求、有限 Fine 本機規則、繁中呈現及安全失敗 |
| [可信 profile](../functions/src/nmt-request-profile.ts) | 在隔離資源不變的前提下明確選擇請求 MIME／詞表契約 |

合法數字時間的公開入口注入測試支持「下午一點 → 1 p.m.／1:00 p.m.／13:00」不再被誤判為新增數量。私有證據另以使用者的原裝櫃句核對，來源原文未變、沒有 auxiliary 翻譯請求。

刻意錯誤的兩點、錯星期或新增金額也不由首版語意檢查否決；`semanticEvaluation=not_evaluated` 明示此限制。一般時間、責任、數量與條件仍是翻譯品質要求，但目前沒有可靠的自動語意判斷能力。舊有限確認核心與其他語意 guard 在新候選中不接入；原未解項目不能因此標為已修正。

## 原樣範圍與歧義處理

- 保護來源 native 範圍、已配置姓名／公司字面值、聯絡資訊、原文 entity／markup、已登錄貿易縮寫及 [9/29 英數符號片段](英數符號字串原樣保留規則.md)；不把任意大寫文字當產品代碼。
- 重疊的原樣範圍合併，native identity 保留其在合併範圍內的偏移。真人身分映射不送 provider。
- 現候選 copy-exact 只接受緊接 cue 的異形引號 `「…」`／`“…”` 或可信 `copyExactRanges`。未加引號的 rate／unit 推斷及 ASCII 直／單引號自動範圍已撤回；原 FAILED 與兩輪紀錄持續保留。
- 段落分隔涵蓋 CRLF、CR、LF 與 Unicode 行／段落分隔字元。HTML 正文一次解碼及呈現後不能新增分隔字元；來源字面的 `&#10;` 仍保持字面文字。
- 字面核對通過只支持已宣告範圍，不表示全句語意正確。

## 配置與操作控制

| 引擎 | NMT_REQUEST_PROFILE | 範圍 |
|---|---|---|
| `nmt-glossary` | 缺省或 `legacy-glossary` | 保持舊 HTML／指定詞表契約 |
| `nmt-direct` | `nmt-direct-v1` | 原文／最少保護，無詞表 |
| `nmt-direct` | `nmt-direct-glossary-v1` | 同一主路徑，加目前核對的指定詞表 |

新候選須由可信配置明確選用，來源文字不能選引擎、模型或 profile。不使用舊 google 分支來繞過受控 client。

[受控 client](../functions/src/nmt-controlled-client.ts) 保留 DEV 身分、NMT 模型、原子預留、operation fence、15 秒 provider 逾時與零重試。跨實例去重及未知狀態的持久儲存實作沒有變更；既有 emulator 證據按原來源核對後重用，不冒稱本次重新執行。

factory 與文字／逐字稿共用入口接入候選，中越仍使用原 adapter。指令、啟停、方向、👆／🚧、提及發送與記錄開關依既有契約。沒有增加聊天記憶、線上 LLM、背景佇列或跨事件翻譯快取。

## 觀測與封裝

operation／品質資料相容增加 `requestProfile`、`adapterVersion`、`protectionVersion`、`validationScope` 與 `semanticEvaluation`。舊資料缺少欄位保持未知。`validated` 狀態仍供舊控制流程使用；新候選要看 `literal-integrity` 範圍，不能把此狀態視為全句語意驗收。

[品質匯出](../functions/scripts/export-translation-quality.mjs) 分開統計 profile、字面核對範圍與語意未評估；這些是 metadata 分類，含失敗／未完整操作，沒有宣稱準確率。

[DEV 封裝](../functions/scripts/prepare-dev-deploy.mjs) 與 [predeploy](../functions/scripts/nmt-admin.mjs) 支持相同可信 profile。無詞表 profile 免讀詞表資源；身份、runtime、帳本、不可重設歷史及必要完整驗證仍保留。既有別名逐 byte 帶入，沒有改動或重新核對 Wei 真人對應；新增／重複／不匹配的受控參數會拒絕。

## 原自動推斷版停止交付與契約重設

最後反例為合成指示 `保持原樣 20 kg Extra Large，請確認 ZX-Q7。`：單位解析未得到明確 operand，但末尾的產品代碼讓「已有保留片段」的 fallback 成立；provider 將原樣內容改動後仍接受。無關字面存在不證明原樣指示已解析，這是同一範圍契約根因，不能再用單位詞表或連接詞例外修補。

DEV 主路徑預設仍為舊 `nmt-glossary`，未修改 DEV dotenv。原自動推斷來源及各輪失敗證據保留為研究／修正候選，停止作交付候選；不進入 provider 評估或發佈。

停止時提出的下一步設計要求：把原樣指示與一般 literal manifest 分成兩項證據：

- 每項原樣指示獨立記錄 cue 範圍、operand 範圍、範圍證據與 `resolved／ambiguous`。找到其他代碼、日期或姓名不能消除該指示的歧義。
- 優先只接受成對引號或可信 metadata 指定的完整 operand；任何未解析指示都依安全政策於 provider 前停止。撤回自動 unquoted 範圍推斷須明列能力差異。
- quote／trusted 可行性與每項指示的完整覆蓋先以公開 adapter 正反例驗證，包含同句多項指示、已知代碼掩蓋未知 operand、重疊 native 與自然正文。未證明完整前不實作擴大 parser。
- 上述為停止時的交接要求，後續執行情形見下節；原兩輪停止紀錄與既有 v21／B 限制持續保留。

## 2026-10-02 使用者繼續下一步：明確範圍能力限縮

使用者明確要求「繼續下一步」，本次實作已撤回原 unquoted rate／unit 自動推斷。每項支持的原樣指示各自保有 cue 與 operand UTF-16 範圍、段落、證據及狀態；任一項 ambiguous 即 provider 前拒絕。一般姓名、代碼、聯絡資訊及自動 literal 保護無權證明該指示已處理。歷史 NDR-F03 與 repairCycle=2 不重置，不宣稱原語法已修好。

明確宣告初版已定向 176 項及完整 2,046 項／工具 45／8／18／11 項通過；首次獨立驗證找到 NDR-EX01：ASCII 直／單引號可能被內部引號或 apostrophe 提早截斷。設計檢討決定撤回這兩種自動範圍宣告，已限縮至異形引號 `「…」`／`“…”` 或可信範圍，不增加姓名或單位例外。原41個探針為39符合／2個EX01失敗，完整報告與來源freeze保存；限縮後定向 4 檔／186 項、完整 60 檔／2,056 項及工具 45／8／18／11 項通過；[獨立複驗](../.local/nmt-direct-development-20261001/explicit-scope/verifier-typographic/verification-typographic.md) 的 58／58 探針通過，四個舊 ASCII 正例保留原預期、另列已撤回且 provider calls=0。21 檔凍結雜湊一致，隔離建置通過；有限 M1／NMT-07 本機範圍可交付。原預期與 FAILED 報告不覆寫。

支持的 cue 為既有「保持原樣／原樣保留／不要改單位／不（要）更改或改變單位」及 `copy exactly`、`do not change/convert (the) units`。此為有限語法；一般自然指示沒有被宣稱可完整理解。新語法只允許每個 cue 緊接空白、可選冒號後的單一 operand。多項內容需各自重複 cue；另一個較晚引號或任意 trusted range 不能替當前 cue 放行。已宣告 operand 內的 cue 是字面資料，完全被可信範圍包含的 cue 亦是資料。可信範圍仍須通過既有 UTF-16、同段落、長度及不重疊檢查。

直／單引號字元本身仍可放入異形引號或可信範圍內，例如 `保持原樣「O'Reilly Logistics」。`；字面內容不改。未加引號的指示即使分母已知或有標點也已撤回，有限契約拒絕例不能算一般譯文語意錯誤。無 copy-exact cue 的普通正文與普通引號內容繼續直接送 NMT。

本次保護版本標為 `nmt-literal-explicit-v1`，只區分能力範圍；受控 profile、舊預設引擎、VI、原子儲存與預留、dotenv 別名均不改。封裝需新增的 `nmt-exact-directives.js`，缺少此 entry 的模擬包會拒絕；未做實際雲端封裝／predeploy。
