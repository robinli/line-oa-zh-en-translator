## 一 問題依據與首版目標

已保存的 DEV 診斷證明：來源的中文時間未被抽取，英文合法數字時間因找不到來源 occurrence 被判為新增內容。目前 00009 的 13 個相關模組與已核對的來源封裝相同，公開 adapter 的離線控制再次重現正確數字時間誤拒。歷史候選未保存，不能回推當時的逐字譯文；使用者提供的原文 NMT 成功經驗是重設基準，尚未由本計畫新增同參數 API 對照。

首版的完成目標是：合法 NMT 回應不再因一般數量、時間、否定或語序未被解析而遭拒，同時維持明確字面內容、提及身分及操作控制的完整性。這個目標不等於所有譯文語意正確；一般 NMT 錯譯列為品質問題，不能以較低拒絕率宣稱整體品質通過。

首版先處理中英雙向，包括共用翻譯器處理的語音逐字稿；音訊取得與辨識流程不重設。中越維持現行 adapter，驗證共用控制沒有回歸；中越領域改善與新主路徑遷移另列研究階段。

最近的唯讀環境證據為 2026-10-01 台灣時間 18:32：DEV `line-auto-translate-bot-dev`、ACTIVE、`linewebhook-00009-vil`。這是計畫建立時的最後核對時間，不是未來操作時的即時狀態。

## 二 新候選的產品契約

下表描述已本機實作的新候選；不改寫總覽第 4～6 節現行 runtime 規則。

| 情況 | 新候選首版行為 | 驗收依據 |
|---|---|---|
| 原文中的一般時間、數量、量詞、動作與條件 | 交由 NMT 翻譯，不先改寫句意或產生語意占位碼 | 合法自然表達不因未解析而拒絕 |
| 明確要求原樣保留的片段 | 以獨立 span manifest 保護與還原 | 內容、次數、段落及 occurrence 關聯一致 |
| API 失敗、無可用回應、長度超限或無法可信還原 | 依既有錯誤流程回覆 🚧 | 不送半截內容，不重試、不換引擎 |
| 一般語意可疑、核對器未支援或 unknown | 首版不作線上否決，列入離線品質評閱 | unknown 不當作正確，也不推定新增或缺失 |
| 字面核對通過 | 只表示該範圍完整，不代表全句語意已驗證 | 報表與 metadata 明示驗證範圍 |

新候選已在本機撤回舊鏈條中一般語意阻擋的權限，包含有限確認核心與其他角色、包裝、費用、數量關係檢查；Fine 的狹義本機短句規則保留。撤回是能力範圍改變，不能稱原 NMT 或 fee／coverage findings 已修好；舊版本已支持的有限能力及原始結果仍保留。

### 明確原樣保留的範圍

- 原生提及片段、已配置的保護姓名與稱呼、可明確指定的公司名及聯絡資訊；人物對應留在伺服器，不傳 userId、groupId 或別名身分映射給 provider。
- 9/29 已確認的英數符號片段、日期、百分比、緊連報價與產品代碼，沿用 [英數保留規則](英數符號字串原樣保留規則.md)。`follow-up` 等片段的可讀性代價繼續存在。
- 明確 copy-exact 內容。開發初期須凍結其範圍判定、重疊優先序與無法唯一定位時的行為，不從模糊語境推測整句都要凍結。

一般金額、幣別、單位與時間仍有保留事實的翻譯要求，但未落入上述字面範圍時，首版不承諾以機械掃描證明其語意。未登錄姓名與公司名不能靠全大寫或猜測自動視為代碼。

## 三 架構與模組邊界

主路徑為：既有事件與顯式產品規則 → 原樣片段政策 → NMT adapter → 字面完整性驗證 → 呈現與 LINE 回覆。品質研究使用既有保存資料，與主路徑分開；首版不新增線上 LLM 呼叫、背景分析佇列或聊天記憶。

| 模組責任 | 工作範圍 |
|---|---|
| 原樣片段政策 | 從未變動的來源文字及可信 metadata 產生 occurrence ID、UTF-16 範圍、段落與保留原因；合併字面範圍，不推斷商務角色 |
| 傳輸編解碼 | 沒有保護片段時採原文 plain request；有片段時使用最少的 notranslate HTML。多段落格式先以代表案例凍結，不用任意標點拆句 |
| 字面完整性驗證 | 只查已宣告的保護片段與可還原性；不掃描全部輸出數字後反查來源，不把原文值強塞回缺失或錯誤片段 |
| NMT adapter | 組裝請求、讀取回應、回傳文字與提及 range；不呼叫來源語意改寫、舊數量還原或舊語意 guard |
| 受控 client 與隔離 | 保留 DEV 身分、專案、NMT 模型、原子計數、operation fence、逾時及零重試；將資源隔離與翻譯 request profile 拆開 |
| 呈現 | 僅處理傳輸層一次解碼、繁中轉換、段落及 LINE 格式；保護片段不被字形轉換或修正文法改動 |
| 品質採集與報表 | 版本、profile、字面驗證範圍與未做語意審核分清；沿用成功內容採集，不保存被拒候選或 SDK 原始錯誤 |

已建立 `nmt-direct-translator.ts`、`nmt-literal-policy.ts`、`nmt-transport-codec.ts`、`nmt-integrity.ts` 及 `nmt-request-profile.ts`，實作範圍與證據見 [本機開發紀錄](NMT主路徑重設本機開發紀錄20261001.md)。既有 `Translator` 的文字與 range 介面沿用，避免重寫整個 webhook。

目前 [nmt-isolation.ts](../functions/src/nmt-isolation.ts) 強制中英使用指定 glossary 與 `text/html`；[DEV 封裝](../functions/scripts/prepare-dev-deploy.mjs) 與 [部署預檢](../functions/scripts/nmt-admin.mjs) 也固定既有引擎。新增 plain／無詞表 profile 必須同步更新受控驗證、工具與測試，不能切到舊 `google` 分支繞過控制，也不能只改 dotenv 讓舊入口接受任意請求。profile 由可信配置選定，不由來源訊息指定。

## 五 代表案例與驗收矩陣

測試以合成資料為主；真人對話、原生身份與完整事件只留 Git 忽略的本機證據。授權範圍內的真人資料僅作本機回歸，不外傳或加入可提交 corpus；缺少的 metadata 不補造。

| 類別 | 正例 | 必須同測的反例與判定 |
|---|---|---|
| 中文時間與自然數量 | 合成裝櫃句的下午一點 → `1 p.m.`／`1:00 p.m.`／`13:00`；一櫃 → `1 container` | 首版主路徑都不因數字形式拒絕；兩點、錯星期、新增金額屬語意反例，記研究 finding，不假稱首版會擋 |
| 時間修飾與角色 | 今天完成確認、下週三裝櫃；提供報告後由另一角色處理 | 把今天移到裝櫃、提供者變處理者；語意核對要指出關係，不能只比較詞是否出現 |
| 字面資料 | `PH-BK`、`USD 8/carton`、`30%`、日期與同段重複代碼 | 改值、精度或字形、遺失、重複、跨段移動與無法唯一關聯，依明確原樣契約拒絕 |
| 原生提及 | 同名不同人、語序改變、Emoji 前後、來源／別名優先序 | 不猜 userId、不以譯文同名搜尋替代 occurrence 還原；群組成員失敗依既有純文字降級 |
| 傳輸與呈現 | HTML 特殊字元、字面 entity、全半形、空段與多段落 | 不雙重解碼、不破壞原樣片段；拒絕缺失內容與無法還原的輸出，不執行輸出 HTML |
| 既有產品規則 | 狹義 Fine 本機回覆、OK／Yes／No、方向不符、相同結果 👆 | Fine?、I'm fine、No discount、只有 @、數字／符號及管理入口，維持既有範圍 |
| 操作控制 | 同批多事件、並行重送、跨實例、採集關閉與開關切換 | provider／LINE started 後逾時不盲目重送；計數／持久狀態失效仍停止；不確定狀態不當成功 |
| 模式與音訊 | 中英文字／逐字稿、新群缺省停用、中越既有路徑 | 不為主路徑新功能改動語音辨識、私訊、中文／拉丁路由或中越 business 設定 |

所有主路徑代表性正例應通過；違反字面契約的反例應拒絕。語意反例另列錯誤種類與觀測能力，不因新版發送成功而改標為正確，也不把其結果混入字面完整性通過率。

## 六 NMT 對照評估

| 組別 | 請求與處理 | 要回答的問題 |
|---|---|---|
| A 原文基準 | 相同 NMT 模型、方向與固定參數，原文 plain，無詞表 | provider 自身能否正確翻譯代表案例 |
| B 新主路徑 | 相同 NMT，僅加入實際所需的原樣保護，無詞表 | 最少保護是否造成語意退化或字面完整性失敗 |
| C 詞表對照 | B 加現行已核對的中英詞表；新 19 詞候選另案 | 詞表對領域詞語的增益及退化，是否值得進首版配置 |

先跑固定的高風險小集，包括自然時間／數量、必要片段混合、角色與否定，再依結果決定擴大。沒有保護片段時 A／B 的 canonical request 若相同，可在該次合成評估共用一個 provider 結果評閱兩條處理路徑；不同請求不可重用。runtime 不新增跨事件快取，不對每則真人訊息做三次翻譯。

## 七 分層檢查與獨立驗證

開發使用 Node 22、UTF-8／Windows CRLF。供 Windows PowerShell 5.1 執行的中文 `.ps1` 使用 UTF-8 BOM；沿用 [本機離線入口](本機離線檢查.md)，不另建弱化的測試或部署入口。

1. 設計初期先跑公開入口的最小正反集合，證明主路徑不需解析一般中文時間也能接受合法英文，不先擴大 parser。
2. 修正候選跑受影響定向測試、必要型別／建置及重播；工具修改另跑對應工具測試。
3. 穩定交付候選完成必要完整離線，凍結實作、配置、案例與證據範圍，再交一位 verifier 用當前應用路徑真正送入 NMT，獨立核對原失敗、相鄰正反例、隔離與是否串回舊 guard；本輪實送合計最多 10,000 個 Unicode 碼點，缺真實證據不得 PASS。
4. 由原寫入者修正 findings，再交同一 verifier 複驗；核心流程的修正複驗同樣須完成本輪真實 NMT，重播不替代。首度系統性誤拒或漏檢先檢討契約；相同根因兩輪未收斂停止逐案補丁，版本及 finding 改名不重置限制。
5. profile 改變後，必要的 operation／帳本持久介面與跨實例故障情境仍須驗證；schema 沒變時沿用未失效證據，新增影響需補相應 emulator 與整合檢查。

主 Agent 是本機開發的預設寫入者；只有工作跨模組且需要明確分工時才委派 planner／implementer，不固定啟動三個角色。派工選用對應 `agent_type`、預設 `fork_turns=none`，交代約 500 字範圍與證據。verifier 檢查期間凍結其範圍，不重做已委派的同一份工作。

專案設定為 GPT-6.1 Sol，主 Agent 推理沿用任務／UI，標準子角色為 Sol／high。執行階段只核對可取得的實際值一次；本次只核對可取得值一次，工具未提供實際主模型／推理；verifier 已明確選標準角色，不能把配置稱為已實核模型值。

## 九 語意核對與中越研究

R-01 先研究事件而非扁平 token 集合：來源／目標各自產生動作、對象、角色、時間、條件／否定、數量單位，以及對應 span、解析範圍與未知部分。結果區分有限範圍一致、矛盾、unknown；沒有解析完整證據時不能推論遺失或新增。

研究必須包含數字與文字時間等價、錯時刻、錯星期、時間移到另一動作、角色互換、未確認變已確認、否定與連接詞、未解析剩餘片段。換語意模型或提示不等於完成驗證；沿用真人資料不外傳及有效 API 授權。
