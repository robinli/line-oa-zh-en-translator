## 能改善什麼

原文 NMT 主路徑可避免不完整的中文時間 parser 拒絕合法英文；相近合成裝櫃句已有真實 NMT 證據。這支持減少系統誤拒，不能代替原始真人句的完整外部驗收或整體準確率。

## S1 已實作範圍

[semantic-contract.ts](../functions/src/semantic-contract.ts) 接受來源、目標各自的事件標註；每個事件明列角色、動作、完成狀態、承諾、否定、時間、數量單位、金額幣別八欄。條件與前後依賴另以有方向的事件關係表達，不只比詞是否出現。每欄為 known 或 unknown；unknown 必須附理由且不能填假值。

known 事實及關係須引用各自正文的精確片段，重複文字用從零開始的 occurrence 指定；本機換算並驗證 UTF-16 位置。已知欄位缺證據、引用另一語言、偽造或重複片段、缺欄位、事件重複、失效關係與非一對一對齊均拒絕。錯誤診斷只含安全代碼。

比較結果只表示人工或模型所提供的標註相同、不同或未知。未對齊事件／關係及未解析片段維持未知；來源不明示主詞或時態時，不據目標文字推定來源資訊。完整字元覆蓋、所有標註值相同或模型自稱 complete 都不能證明整句正確。結果固定為 offline_research、semanticTruth=not_verified、wholeSentence=not_certified、runtimeDecision=none。

本階段沒有自然語言抽取器；33 項測試使用人工標註，驗證證據、未知及比較契約，不能稱為自動錯譯偵測準確率。也沒有 arrange/payment 替換、一般時間 parser 或線上二次生成。

## 後續實證與驗收

1. 分別驗證自動標註的覆蓋與正確性。固定來源與譯文，先納入忠實時間變體、安排／已執行、角色互換、否定與條件方向，另測省略主詞及未解析剩餘片段。模型與提示不接觸人工預期標籤；證據命中不等於語意正確。
2. 比較已保存 NMT 與新的單次生成方式，由獨立評閱核對交易狀態、角色、時間、數量及字面。正確輸出不能新增誤判，重大錯譯要指出正確文字與關係，未知不能假稱一致。抽取與生成分開報告，不能用多拒絕掩蓋生成沒有改善。
3. 小集支持可行性後才凍結未見案例擴驗；依研究、修正、交付候選分層完成檢查。首次系統性失敗先檢討契約，同根因兩輪未收斂停止補丁。
4. 有足夠生成品質證據才評估 runtime 整合；目前每事件單一 provider、防重送、字面及原生提及還原、中越、既有別名契約仍有效。真實 API 與部署按各自有效授權處理。
