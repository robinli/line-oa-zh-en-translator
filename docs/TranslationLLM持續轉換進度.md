## 本階段實作

- 普通姓名第一輪保留原姓名供模型理解；若品質不過，第二輪才改用姓名加唯一識別碼。兩輪都驗證姓名完整、次數及邊界；不能翻成別名、代名詞而漏掉原姓名。原生 @ 使用帶 occurrence id 的 notranslate span 顯示原姓名，再轉回獨立標記及來源 UTF-16 對應，不以普通姓名猜 LINE 身分。
- 術語表 v8 位於 us-central1，中英 16 詞、英中 28 詞；客戶業務負責人及「客戶的業務負責人」譯為 customer account owner，和銀行帳戶持有人區分。曾試驗的「可以請→can ask」造成錯誤文法，已移除，不用整句測試答案當術語。
- 完整保護巢狀 literal entity，例如 &amp;amp;、&amp;#39;、&amp;amp;#39;；不把後綴留給模型改寫。網址內 entity 由完整網址保護，不再和 entity 的範圍搶占。
- 修正網址掃描：遇常見全形中文分隔標點即結束網址，避免把「；請寄到」一起吞入保護值；仍保留中文 URL 路徑及 query。這個共用修正也改善 Gemini 的文字保護，已隨第 16 版部署。
- 英文正文若仍有未受保護的漢字會拒絕；受保護原生姓名的中文不受影響。
- 算式原式、前後負號、百分比及運算子均驗證；允許運算子周圍空白並還原原式，不允許數字內新增空白，不允許把 612+28 偷改成 612+28% 或外加等號。
- 修正特殊符號姓名的 regex 跳脫，以及短識別碼偶然和內部 token 前綴重疊造成的誤拒。
- 加上有限價格關係守門：拒絕把「未提出兩個金額」變成「報價低於金額」、把單價當地點、或把不含運費的價格稱成運費；這些是針對已觀察錯誤的有限檢查，並非通用語意判定。
- 保留先前的金額單位整組保護、引用輔助翻譯、一次 transport 解碼、繁體轉換、段落及原生提及還原；只在還原原值前修正限定術語文法殘留，例如 freight are、重複的 yet 和負責人人。
- 最多兩次品質嘗試、每次 15 秒，SDK 不重試，服務錯誤不跨引擎備援，未驗證譯文保持安靜不回覆。

- 新增原生提及的有限主詞狀態及禁止命令檢查，保留同名不同人的責任；有效「先／暫時不要付款」可接受，但「還沒付款」不能代替禁止命令。
- 英文提及與相鄰單字補空格，同步維護 sourceStart 與輸出位置，最後重查 4,500 UTF-16 上限。
