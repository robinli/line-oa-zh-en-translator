# 商務翻譯優化

> **必讀入口：** 開始新工作前先閱讀 [系統規則與知識總覽](系統規則與知識總覽.md)。本文件保留功能細節與各階段驗證紀錄，歷史版本編號不代表目前仍在服務的版本。

## 範圍

本階段針對多方貿易群組的文字與語音逐字稿翻譯，新增商務翻譯規則、貿易術語指引、重要資料保護與驗證；修正含中文 @ 名稱的英文訊息方向判斷，並強化相同譯文不回覆的空白比對。第一階段未包含原生 @ 通知；原生提及已於 2026-09-22 部署至 linewebhook-00013-tif，詳見 [LINE 原生提及](LINE原生提及.md)。

## 翻譯規則與保護

- 區分底價、成本價、出廠價、基礎價格與對客報價；保留提議、疑問、否定、尚未確認與已確認的差異。
- 保留多方角色，禁止把特定人名換成「你／我們」而改變責任歸屬。
- 保留 CNF、CFR、CIF、FOB、EXW 等原始縮寫；不得自行加入含稅、佣金、保險或其他未明說的費用。
- 將原文數字、算式、幣別、縮寫單位、已知人名、產品代碼及原生 @ 顯示文字轉為逐一對應的標記；模型能看到標記的原始值與種類，但必須輸出標記。
- 每個標記必須恰好出現一次才可還原。新增數字、遺漏或重複標記、未保護的貿易縮寫會被拒絕；已設定的人名不應另外重複輸出。
- 對明確的中文「底價／出廠價／成本價」增加英、越譯詞檢查；英翻中若輸出完全没有中文則拒絕。
- 驗證失敗最多重試一次。仍失敗或翻譯服務不可用時靜默略過，只記錄後台錯誤，不回覆失敗提示、不發送未驗證的報價，也不自動退回未受保護的舊翻譯。
- 模型回覆必須完整、為指定 JSON 格式；截斷、封鎖或服務失敗均不回傳片段譯文。
- 不記錄原文、音訊、譯文、人物對應或驗證失敗的內容；診斷只含錯誤類別。未加入跨訊息聊天紀錄。

這些驗證可攔截數值或標記損壞，不是完整語義正確性的證明；角色、否定與費用歸屬仍需用評估案例及人工抽查驗收。未列入名單的人名由翻譯規則保留，但沒有逐項字元保證。中文數量詞、未辨識的產品編碼與非縮寫單位也需要人工檢視。

## 訊息方向與不回覆規則

原生 mention metadata 的 index/length 以原始訊息 UTF-16 位置處理，排除顯示名稱後再判斷正文語言。顯示名稱保持在翻譯輸入的受保護範圍內，新版會依原文指定身分與群組成員確認結果保留原生 @ 提及，詳見原生提及文件。沒有有效 metadata 時，不猜測姓名範圍，沿用正文判斷。

- 英文正文＋中文 @ 名稱：中英雙向／英翻中模式翻成繁體中文；中翻英模式略過。
- 中文正文照原模式翻成英文或越南文。
- 群組先取得翻譯結果，再比對原文與譯文；先統一全半形相容字元，再忽略首尾與重複空白、常見標點兩側的空白，相同就不回覆。
- PP-BK?、PP-BK ? 與 PP-BK？視為相同；沒有「產品代碼一律不翻」的排除名單，大寫英文也不因此略過。
- 一對一相同譯文、語音「逐字稿＋譯文」的行為維持。較長的文字回覆依 LINE 單則上限分段，不截斷內容。

## 引擎與設定

新引擎使用同一 Google Cloud 專案的 Vertex AI Gemini，因為原本 Cloud Translation translateText 沒有自訂 system instruction，難以直接套用上述多方商務規則。舊引擎保留為明確的操作設定選項。

| Firebase 參數 | 預設 | 用途 |
|---|---|---|
| TRANSLATION_ENGINE | business | 新商務翻譯；google 為舊 Cloud Translation |
| TRANSLATION_MODEL | gemini-3.5-flash | 支援結構化輸出與系統指令的 Gemini 模型 |
| TRANSLATION_LOCATION | global | 模型 API 位置，不是 Function 部署區域 |
| TRADE_PROTECTED_NAMES | Wei,Shan,Eric,Kash,Kumar,Kumaran,Niranjan | 逗號分隔、大小寫不敏感的人名保護清單；不包含 LINE userId |

目前為所有啟用翻譯的聊天室共用規則，語言方向、文字／語音開關及既有設定仍由各聊天室控制。沒有依群組不同名單的管理指令。

每次模型請求逾時為 15 秒，SDK HTTP 自動重試關閉；只有品質驗證失敗才重試一次。多個 webhook events 仍順序處理。聊天內容作為 JSON 資料，來源中的「忽略規則」等文字不是指令，模型沒有工具或外部操作權限。

## 評估

一般驗證：npm.cmd run verify。

合成評估：先建置，設定 GOOGLE_CLOUD_PROJECT，再執行 npm.cmd run evaluate:trade --prefix functions。預設使用 Application Default Credentials；受控驗證也可透過只在程序生命週期存在的 TRADE_EVAL_TOKEN。程式只讀取已提交的虛構案例，不接受客戶對話檔案參數。結果在 Git 忽略的 .local/trade-evaluation.json。

合成資料含底價、出廠價、包含／另加、人物角色、未知費用、代碼與中英／中越方向。機械檢查只是第一層，必須另讀完整輸出確認語義；測試中的期望片段不等於模型整體準確率。

使用者提供的真實對話僅作本機回歸測試。實際 LINE ID 保存在 Git 忽略的 .local/line-member-aliases.json，不進入翻譯提示或評估資料；指定提及僅由伺服器與 LINE 處理身分對應。
