## 範圍與資料分工

- 從新版生效後開始，不回補過去聊天；既有 lineTranslationMessages 及其他歷史保持。第一版只做後端保存及維運檢查，不新增查閱介面。
- 所有開啟記錄群組的訊息先保存至 lineConversationEvents；文字、附件、貼圖、位置、提及、引用、管理指令、正常略過及錯誤均包含。另存編輯版本、收回、成員進出、機器人加入／離開與可得其他群組事件。
- lineConversationMessages 保存同群同訊息目前版本、收回標記及附件狀態；lineConversationArchiveJobs 保存背景下載／清除工作。原始事件時間與接收時間分開，事件 ID 去重，訊息目前版本依事件時間／事件 ID 排序，不能以重送或亂序覆蓋較新版本。
- 附件原始 bytes 保存於各環境的 `{projectId}-conversation-archive` 私有 bucket，不儲存在 Firestore。支援 LINE content API 可取得的圖片、語音、影片與檔案；貼圖保存識別及可得文字，外部提供者無法透過此 API 取得原檔時標示 missing，不猜測或任意抓取外部 URL。
- 只有需要進入翻譯流程的訊息才新增 lineTranslationMessages，透過 archiveEventId 連回歷程；成功、失敗、品質拒絕及相同譯文回 👆 均保留。正常略過、非文字與管理指令不再建立新版翻譯記錄。
- 語音原檔保存與語音辨識開關獨立；只保存現有流程取得的逐字稿，不為記錄另呼叫辨識、翻譯或模型。
- 本系統回覆以 botReply 歷程保存每次實際 LINE 訊息 payload、來源事件、可得回覆訊息 ID 與 prepared／accepted／rejected／unknown。提及格式 400 降級的兩次實際嘗試分別保存；accepted 只表示 API 接受。

## 保存優先、附件與完整性

簽章及 JSON 驗證後，先交易保存事件與可得附件工作，再進入現有操作 claim、翻譯或回覆。來源保存失敗／不確定回 HTTP 503；LINE 重送可能延後或無法即時回覆，但不重做已開始或結果不確定的翻譯／LINE 操作。

需要翻譯時先保存翻譯原文與關聯，再呼叫翻譯；正文成功入庫才開始模型。所有 webhook 保存與回覆仍受 receipt+50秒、既有中英40秒截止及 DeadlineScope 約束；附件由 Firestore 建立事件觸發 `conversationArchiveWorker`，不在 webhook 下載。

工作租約及 owner 防並行；下載最多八次實際嘗試，逾時／暫時故障重試，已完成不重送；永久不可取及耗盡嘗試標示 missing。原檔串流處理，保存大小、SHA-256、content type、物件路徑。清除工作持續重試，不以八次下載上限放棄清除。

收回先保存不可復原標記，封鎖延遲翻譯記錄、引用、案例／草稿快照、回覆及附件回寫，再背景清除原文、編輯版本、可得逐字稿、譯文、NMT 傳輸內容、回覆本文、原始附件與可關聯副本。附件下載與收回競爭時完成後再次核對並刪除晚到物件。保留最小識別、事件／時間及清除結果；系統外已交付副本無法回收。

專用 bucket 採 ASIA-EAST1／STANDARD、uniform bucket access、public access prevention，關閉 versioning、soft delete、retention lock，不提供公開下載 URL；未收回資料持續保存至手動清除。

維運入口：建置後執行 `node functions/scripts/conversation-archive-admin.mjs --project=專案 --credentials=隔離ADC路徑 --mode=check`，只印配置／群組／事件／工作／附件數量。`--mode=prepare` 僅允許 DEV，執行上述已知群組相容與配置初始化；不改正文、不發 LINE、不呼叫翻譯。

接收診斷 `archive_received`、失敗 `archive_store_error`、回覆完成保存失敗 `archive_reply_store_error` 不印正文或身分映射。資料庫已保存筆數不能證明 LINE 所有事件皆送達，需與安全接收日誌核對；未完成附件／回覆不確定明確顯示，不能標成完整。
