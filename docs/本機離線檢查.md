# 本機離線檢查

2026-09-29：以 `scripts/check-local.ps1` 統一本專案的 Windows 本機檢查。它定位自身所在專案，固定 Node 22、子程序 PATH 與 `functions/` 工作目錄，提供定向測試及完整離線檢查。工具不下載 runtime／依賴、不登入雲端、不執行部署或翻譯 API。

## 使用方式

使用 Windows PowerShell 5.1，先確認專案依賴已安裝。若 PATH 中的 Node 已是 22，可省略 `-NodePath`；若不是，明確指定本機已安裝的 Node 22 `node.exe`，工具會檢查版本而不自動改用其他版本。下例的 `$node22` 須先設成實際絕對路徑；不把個人 npm 快取路徑寫死在版本控制中。

```powershell
# 在專案根目錄的 PowerShell 執行；$node22 為已確認的 Node 22 完整路徑。
& .\scripts\check-local.ps1 -NodePath $node22

# 只跑本次影響的應用測試，名稱以 functions/ 為基準。
& .\scripts\check-local.ps1 -NodePath $node22 -Mode targeted -Tests @('src/literal-codes.test.ts', 'src/nmt-pricing.test.ts')
```

從其他目錄啟動時，用腳本的完整路徑；`-Tests` 仍以該腳本所屬專案的 `functions/` 為基準。支援現行 `src/` 內測試檔的相對或絕對路徑，不接受模糊檔名、萬用字元或 Vitest 旗標。每一個指定檔都須存在；混入一個打錯的名稱也會在執行前失敗。

完整模式依序執行型別檢查、所有應用測試、建置、NMT 工具、品質工具、部署工具及本機檢查工具測試。`targeted` 只跑指定的應用測試，不等於型別、建置或完整驗收；工具程式修改另跑相應的 `test:*` script，最終候選仍完成完整檢查。

完整模式會從 npm 提供的 CLI、指定 Node 同目錄的 npm 或 PATH 中 `npm.cmd` 所在安裝找 `npm-cli.js`；找不到時用 `-NpmCli` 指定完整路徑。所有 npm 及其 lifecycle 子程序都使用同一 Node 22。環境不符即停止，不以臨時下載或降低版本條件繞過。

直接使用 npm 時，也須先把 Node 22 目錄放在目前程序的 PATH 前端。既有 `npm run verify` 及 `npm --prefix functions run verify` 保留；`verify.mjs` 會在執行檢查前確認 Node 22，再將相同 runtime 傳給子程序。

## 測試範圍及日誌

- `functions/vitest.config.mts` 將 root 綁定設定檔所在的 `functions/`，只收集 `src/` 下的 test／spec 檔，排除 `node_modules`、`.local`、`lib`、`coverage`。npm test／watch 與定向入口均明確指定此設定；不要從根目錄裸跑無設定的 Vitest。
- 定向模式以精確檔案集合收集，另核對收集身分，避免 `.test.ts` 連帶選入 `.test.tsx`；檔名中的括號按字面處理。完整模式清除前次定向篩選，不沿用局部範圍。
- 沒有符合條件的測試檔、測試檔中沒有測試，或整輪只有 skip／todo 而無實際執行，皆為失敗；完整及定向模式共用執行數檢查，正常執行與 skip 混合可依實際結果通過。不要以 CLI 覆寫 config 的 reporters，否則會移除執行數檢查；受支援的本機入口不提供這種覆寫選項。
- 每次檢查在所屬專案 `.local/checks/` 產生獨立 UTF-8 日誌，包含 Node 版本／路徑、工作目錄、範圍、完整輸出與退出碼。畫面顯示範圍及結果，失敗時另外顯示末段診斷；交接引用日誌路徑，不貼整份輸出。
- PowerShell 入口保留原生非零退出碼及 stderr，例如子程序退出 23，入口亦退出 23；前置條件錯誤退出 1。PS5.1 的 stderr 會呈現為 ErrorRecord，可能加入換行及診斷欄位，日誌不作逐 byte 的原始串流承諾。檢查後恢復該 PowerShell 程序的 PATH、定向篩選、位置與輸出編碼。
- DEV 封裝將此 PowerShell 入口與 Vitest 設定納入必要檔案及雜湊檢查，並在包內沿用完整 verify；不修改歷史封裝或把新結果標成舊包證據。
