## 1. 工作前必讀與文件維護

1. 先讀本節，再按下方索引定位相關規則、實作與測試；同任務未變內容不重讀，文件不能取代實作核對。
2. 確認工作區既有異動、最新需求與有效授權；保留其他任務的變更，使用者最新明確需求優先。
3. 文件、程式與需求不一致時查證來源；只釐清會影響行為的實質歧義，已有授權不重複詢問。
4. 程式、設定與文件使用 UTF-8／Windows CRLF；本機預設 `powershell.exe`，其他 shell 先確認存在，供 PowerShell 5.1 執行的中文 `.ps1` 使用 UTF-8 BOM／CRLF。
5. 理解或定位程式時，搜尋優先使用 `rg`／`rg --files`。
6. 遵循 [Codex 開發流程](Codex開發流程.md) 的最小角色、代表性正反例、根因收斂與分層驗證；文件／格式／Agent 設定只做必要靜態檢查。
7. 規則改變時更新本總覽及相關細節文件，並在 [專案日誌](專案日誌.md) 加一句摘要；詳細修正過程及測試日誌留在各自證據。
8. 分別報告開發、測試、部署及人工驗收狀態；局部 PASS、HTTP 200 或部署成功僅支持各自範圍，未解 findings 與停修／付費暫停持續有效。

## 3. 指令、權限與聊天室設定

下表 /我的ID 僅限私訊；DEV /翻譯錯誤 僅限指定管理者私訊，其餘指令限群組；私訊輸入 /翻譯設定 也不回覆（回報草稿期間依表單輸入處理）。

| 指令 | 功能 |
|---|---|
| /中翻英 | 設為 zh-to-en 並啟用文字 |
| /英翻中 | 設為 en-to-zh 並啟用文字 |
| /中英翻譯 | 設為 zh-en 並啟用文字 |
| /中越翻譯 | 設為 zh-vi 並啟用文字 |
| /啟用文字翻譯、/停用文字翻譯 | 只修改文字開關，保留模式與語音開關 |
| /啟用語音轉文字、/停用語音轉文字 | 只修改語音開關，保留模式與文字開關 |
| /翻譯設定 | 顯示模式、文字與語音開關及所有操作指令（含 /我的ID） |
| /我的ID | 僅一對一私訊回覆發送者自己的 LINE userId；群組中忽略 |
| /開啟記錄、/關閉記錄 | DEV 指定管理者於群內切換本群採集，全部群組缺省開啟；關閉保留歷史且不影響翻譯 |
| /翻譯錯誤 | DEV 指定管理者私訊搜尋已知群組紀錄或手動新增錯誤案例；支援 /返回、/取消，草稿閒置 30 分鐘失效 |

- 指令先去掉前後空白，內容必須完全相符。
- DEV 已移除 /啟用翻譯、/停用翻譯、/翻譯狀態；群組與私訊輸入這三個舊指令時直接 ignored，不讀寫設定、不回覆、不翻譯。/翻譯設定 合併狀態與操作清單；清單不重複列出查詢入口本身，/我的ID 仍僅私訊有效。
- 群組只有 LINE_OWNER_USER_ID 指定的單一帳號可修改設定；所有群組成員可查詢狀態。不能以顯示名稱或聲稱為管理員來取得權限。
- 一對一聊天室不能修改或查詢設定，即使發送者是指定管理員也一律忽略；群組缺少來源 userId 的設定修改不執行。
- 切換模式會開啟文字翻譯，不連動語音開關。
- 加入群組時讀取現有設定並回覆狀態／啟用說明，不重設舊設定。
- 語音逐字稿中的指令只當作內容，不能執行設定變更。
- 每個群組各自保存設定；不得因更新某群組而重設其他群組。

Firestore collection 共用 lineTranslationGroups：使用群組原始 groupId 作為文件 ID；歷史私訊 user:{userId} 文件保留但不再使用，無須刪除或遷移。欄位為 textTranslationEnabled、audioTranscriptionEnabled、translationMode、changedBy、changedAt。

舊 enabled 欄位的相容規則：兩個新開關各自優先讀明確的布林值，缺少或非布林時才沿用 enabled === true。修改新開關以 merge 寫入，不改舊 enabled，不覆蓋另一個開關。缺少或無效模式使用 zh-en，既有四種合法模式與開關直接沿用。切換模式不重設語音開關，不自動遷移或寫入正式聊天室。

## 4. 語言判斷與回覆規則

文字先依有效 LINE mention metadata 排除原生 @ 顯示名稱，再判斷正文；索引採原始文字的 UTF-16 位置，不能先 trim 再套索引。沒有有效 metadata 就不猜姓名範圍。

目前用字元規則判斷方向，不是完整語言辨識：含程式辨識範圍內的漢字視為中文，否則含拉丁字母視為模式中的英文或越南文。中英混合視為中文；中越模式中的拉丁文字按越南文處理。

| 模式 | 中文正文 | 英文／拉丁文字正文 |
|---|---|---|
| zh-to-en | 翻成英文 | 👆 |
| en-to-zh | 👆 | 翻成繁體中文 |
| zh-en | 翻成英文 | 翻成繁體中文 |
| zh-vi | 翻成越南文 | 按越南文翻成繁體中文 |

語音逐字稿使用相同的方向規則，但逐字稿沒有 LINE 原生 mention metadata。純數字、符號、Emoji 不呼叫翻譯服務；僅有原生 @ 名稱而沒有可翻譯正文時也不因姓名觸發翻譯。

### 單獨簡短回覆不翻譯

- 群組文字整則只有 OK、Yes 或 No 時，在呼叫翻譯前略過並回覆 👆，計為 processed；適用所有翻譯模式。私訊由入口直接忽略所有非 /我的ID 訊息。
- 忽略大小寫、全半形、前後空白及句尾常見標點（句點、逗號、問號、驚嘆號、省略號）。
- 含其他文字、數字、Emoji 或原生 @ 名稱仍走原有流程；例如 No discount、Yes, please confirm、No. 123 不可略過。不擴充至 Okay 等其他詞。
- 不解碼字面的 HTML entity；語音逐字稿與管理指令維持既有行為。

### dev 相同譯文回覆 👆

- 適用群組文字；先取得翻譯，再比對原文與譯文，不能改成產品代碼黑名單。
- 比對採 NFKC 全半形相容正規化、去首尾空白、合併連續空白／換行，並忽略程式指定的常見標點兩側空白。
- PP-BK?、PP-BK ?、PP-BK？會視為相同。保護 PH-BK／PP-BK 是防止改動產品代碼，不是禁止翻譯。
- 大寫英文不能一律當作代碼跳過。
- 相同時只回覆 👆，不附加 @、原文或說明，計為 processed；不新增失敗記錄。
- 群組語音逐字稿回覆不套用相同譯文略過；私訊根本不執行翻譯。

### dev 翻譯錯誤與阻擋回覆 🚧

- 群組文字翻譯錯誤、品質拒絕、初始化／輸出格式阻擋及文字長度超限，只回覆 🚧 並保存原文；不得發送未驗證譯文、半截內容或自動切換引擎。
- 語音下載／辨識／翻譯失敗、時長／大小／逐字稿長度超限也回覆 🚧，取代原超限提示；能取得逐字稿就保存，尚未取得則 sourceText=null，絕不保存音訊。
- 功能停用、OK／Yes／No、方向不符、純數字／符號的群組訊息回覆 👆，不新增失敗紀錄；DEV 已開啟記錄的群組另保存內容及處理結果，私訊與不支援事件按其入口規則處理。管理指令與設定讀取錯誤不納入既有翻譯失敗記錄；兩個記錄開關只保存操作資訊，不加入品質樣本。
- 語音成功仍回覆逐字稿或「逐字稿＋空行＋譯文」；即使譯文相同也不改成 👆。
- 失敗記錄保存在 dev 的 lineTranslationFailures，事件 ID 優先防重複，缺少時使用群組＋訊息 ID，皆缺少才使用隨機鍵；首筆內容與時間不被重送覆寫，保存至手動清除。
- 記錄與 🚧 回覆各自嘗試並等待完成，單項失敗不阻止另一項；兩者任一失敗只記安全後台診斷，無背景補寫佇列。處理失敗仍計 failed，繼續處理同批事件。
- LINE 發送失敗不當作翻譯失敗入庫，也不補送另一個符號或重用 replyToken；不變更既有 replier 的明確 400 提及格式降級行為。

## 5. 中英商務翻譯知識與不可混淆的概念

本節為 DEV 中英需求與驗收原則；中越 NMT 不載入商務術語、預設人名或商務驗證。

| 原詞／情境 | 翻譯原則 |
|---|---|
| 底價、最低可接受價格 | lowest acceptable price／minimum acceptable price；不是 base price、cost price，也不是已成交價 |
| 成本價 | cost price |
| 出廠價 | ex-factory price；不能自行加上運費或把它視為完整到岸報價 |
| 基礎價格 | base price |
| 報價、對客報價 | quotation／quoted price、price quoted to the customer |
| best price | 最優惠報價；原文未表明最低／底線，不自行加強成「底價／最低價」 |
| account owner／owner of the account | 客戶業務情境是「客戶業務負責人／該客戶的負責人」；銀行、登入帳戶依各自情境 |
| sales representative | 業務代表 |
| freight／shipping cost | 運費 |
| commission、markup、surcharge | 佣金、加價、附加費；三者不可自行互換 |
| taxes and duties | 稅費；不能由 CNF 推論已含稅 |
| including／含 | 包含在既有金額內 |
| additional／另加 | 在既有金額上另加；未知項目不得擅自命名為運費、佣金或稅 |

## 7. LINE 原生 @ 提及

以下 Wei 等稱呼別名配置僅中英程式使用；原生 mention metadata、群組成員驗證與 LINE 回覆限制兩程式共用，中越採第 6 節的 HTML span 還原。

## 8. 架構、回覆及事件處理

處理流程：同一 LINE POST → 簽章與事件驗證 → DEV 穩定事件的持久處理權 → 私訊處理 /我的ID 及 DEV 指定管理者錯誤回報，其餘忽略；依各群記錄開關採集 → 群組指令／設定 → 方向判斷／音訊辨識 → 依模式取得中英或中越程序 → 相同譯文判斷 → 必要時確認群組成員 → LINE Reply API。

getTranslationProgram(mode) 只在需要翻譯時初始化，成功程序快取於實例；中英設定錯誤不阻止中越、設定指令或純語音辨識。zh-vi 不載入中英稱呼別名；原生 mention metadata 仍支援。

- 僅接受 POST；其他方法 HTTP 405 並附 Allow: POST。
- 用未修改的 rawBody 與 LINE_CHANNEL_SECRET 計算 HMAC-SHA256，以 timingSafeEqual 比較；不可先重組 JSON 才驗證簽章。
- 缺少或無效簽章 HTTP 401；JSON／events 格式錯誤 HTTP 400。
- 有效事件逐筆循序處理，正常空 events 回傳 HTTP 200。
- 單筆失敗不終止整批；統計 processed、ignored、failed，整體仍回 HTTP 200。因此 HTTP 200 不代表每則譯文成功。
- DEV 以持久 operation 控制同一穩定事件的副作用；關閉內容採集不關閉去重，同文不同事件分開處理，缺少可靠識別時明列無法去重。
- provider_started 與字元預留在同一交易更新；結果不確定時不重呼 provider、不盲目補送 LINE，不自動接管 stale lease／排程恢復或 TTL，也不回退帳本／刪除操作以重試。
- 操作紀錄只存識別雜湊、狀態、版本與安全統計，詳 [去重與觀測](DEV事件去重與翻譯觀測.md)；持久控制不保證外部 exactly-once。
- 一般回覆使用 text，含有效提及使用 textV2；沿用收到的 replyToken，不任意改成主動 push。
- 回覆最多五則、單則最多 5,000 UTF-16 單位；整段回覆最多 24,000，超出拒絕。提及／轉義造成超過五則時，改完整純文字分段，不截斷內容。
- 語音辨識用 Speech-to-Text v2、long 模型、自動標點；語言為 cmn-Hant-TW＋en-US，或中越模式的 cmn-Hant-TW＋vi-VN。
- 語音有譯文時回覆「逐字稿＋空行＋譯文」，不添加「語音轉文字／中文／英文」等標題。

## 12. 驗證、部署及回復

核心翻譯流程交付依 [開發流程](Codex開發流程.md#4-實作收斂分層驗證及付費測試) 完成每輪不超過 10,000 字元的真實 NMT 驗收；離線、健康檢查與部署成功各自只支持其範圍。GCP 服務／API 準備須在開工前按計畫完成。

- 本機定向與完整檢查依 [本機入口](本機離線檢查.md)，使用 Node 22、指定工作目錄及現行測試範圍；mock 與真實 API 證據分開，型別／測試／建置支持各自宣稱範圍。
- DEV 使用 [隔離封裝工具](DEV部署封裝工具.md)，新包建置、完整 verify 與雜湊凍結；原樣帶入既有別名，不更新或清空 Wei。來源改變按失效證據重驗。
- 實際部署在有效授權內走既有入口，核對身分／專案、帳本、術語表及 Firebase predeploy；不省略包內或 predeploy 必要完整檢查，不從主工作區直接覆蓋正式原碼。
- 部署前保存版本、參數及必要資料；完成後確認 Function ACTIVE、Cloud Run revision／流量、參數／Secret 綁定與來源一致性，按變更做必要合成檢查。
- CLI 非零退出但日誌顯示更新成功時，先唯讀確認雲端及部署後檢查；不盲目重複部署，也不僅憑退出碼宣稱完成。
- HTTP 200 與 LINE validate/reply 只證明其檢查範圍；群組成員、手機顯示／通知及真實品質另做人工驗收。不為測試中斷正式模型、輪替 Secret 或改群組設定。
- 正式回復依第 9 節指定 Git 原碼；DEV 相容回復保留 A 的 operation schema、累計帳本及 migration history，不能直接切回不讀去重狀態的 00007，不能清空操作或回退帳本重試。
- 舊 revision 紀錄不保證映像仍存在；回復前確認來源與相容性。DEV 部署映像現有保留最新三版政策，建置快取保留，實際清理由背景排程執行。

部署與合成檢查不代替整體品質或真人驗收，現行未解項目依第 2 節追蹤。
