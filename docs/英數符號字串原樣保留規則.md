# 英數符號字串原樣保留規則

2026-09-29 使用者明確改變規則，並確認以下範圍：只保留符合條件的片段，其他正文照常翻譯；句尾標點不構成代碼；包含日期、百分比等「數字＋符號」。

## 規則與例子

辨識不含空白的連續英文字母／數字與指定符號組合，至少有一個英文字母或數字，以及一個指定符號：`- / $ % * + = . ~ ^ !`。不區分大小寫，對應的全形字元也可辨識，最終保留來源字形與數值。

- `PP-BK`、`abc/def`、`A+B=C`、`28/09/26`、`30%`、`$50`、`C++` 原樣保留。
- `Please check PP-BK.` 只保護 `PP-BK`；`Please check` 照常翻譯，句尾句點交由一般翻譯處理。
- `Hello!`、`Follow up.`、`Mr. Shan` 不因單字末尾的句點／驚嘆號而被當成代碼；位於字串邊緣的句點、驚嘆號、不完整斜線不納入保護範圍。
- `A + B` 有空白分隔，不視為單一連續代碼；原有數值／算式檢查仍適用。
- 本規則依字元結構，不查英文單字詞典，因此緊連的 `follow-up`、`ex-factory` 也會原樣保留。
- `USD 8/carton` 的緊連片段與既有金額範圍合併保護，最後保留 `USD 8/carton`；`USD 8 / carton` 有空白分隔，仍由原有商務規則翻譯每箱等單位，保留金額。
- `2.5 公斤` 中的小數仍由既有數量檢查保留，單位可依翻譯方向轉為 kg；不因小數而把中文單位一起凍結。

只包含保護片段而沒有可翻譯正文時，翻譯器可直接返回原文，不新增翻譯 API 呼叫；群組文字沿用相同譯文回覆 👆 的行為。這不是整則訊息的代碼黑名單。

## 保護與驗證

本機中英 NMT 與保留的 LLM 候選在 HTML 中將符合片段標示為不可翻譯，驗證內容、出現次數與段落並還原來源內容；中越 NMT 使用同一辨識規則，且不載入商務術語／人物規則。英文與中文方向、群組文字及共用翻譯器處理的語音逐字稿均適用。

原生 @ 提及、聯絡資訊及來源字面標記維持原有優先順序；一般代碼不會新增 LINE 提及身分，不占中英的原生提及 20 項上限。數量、金額、分母與語意檢查保留；原樣片段被改動、遺失、重複或移至另一段仍拒絕，沒有自動改用其他引擎。

來源與譯文掃描分開：來源辨識新代碼，輸出掃描沿用數值辨識，避免把輸出中的普通片段誤認為新增受保護項目。同一算式有緊連及含空白兩種寫法時，獨立追蹤各次出現，最終恢復各自的原始空白。

明確要求原樣保留的混合報價（如 `保持原樣 USD 8 / 袋-XL。`）會在完整分母檢查通過後，保護中文單位及代碼再還原，避免合法保留的漢字被誤判為正文未翻譯；一般正文的目標語言檢查維持原規則。

## 與 Action Plan 診斷的關係

`28/09/26` 現在會使用不可翻譯 span，避免先以普通日期明文送入再只接受有限字面格式的交界問題。測試用手工假回應驗證多行正文、日期、百分比與代碼混合的完整 NMT 路徑。

這是依使用者新要求的修正，不是重播當時遺失的候選譯文；歷史事件的實際觸發片段仍無法唯一確認。[先前診斷](ActionPlan翻譯拒絕離線診斷.md) 保留原始結論與限制。
